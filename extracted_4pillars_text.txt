1.1.3 ที่อยู่ในเครือข่าย: IP Address และ MAC Address
IP Address — ที่อยู่ของอุปกรณ์บนเครือข่าย เปรียบเหมือนที่อยู่บ้าน เปลี่ยนได้ตามเครือข่ายที่เชื่อมต่อ
IPv4 ยาว 32 บิต เขียนเป็นเลข 4 ชุดคั่นด้วยจุด แต่ละชุด 0–255 เช่น 192.168.1.10 (มีประมาณ 4.3 พันล้านที่อยู่ ซึ่งไม่พอใช้แล้ว)
IPv6 ยาว 128 บิต เขียนเป็นเลขฐาน 16 เช่น 2001:db8::1 ที่อยู่เยอะมากพอสำหรับอนาคต
Public IP — ใช้บนอินเทอร์เน็ต ไม่ซ้ำกันทั่วโลก  |  Private IP — ใช้ภายในเครือข่ายบ้าน/องค์กร ช่วงที่พบบ่อย: 10.x.x.x, 172.16–31.x.x, 192.168.x.x
Subnet Mask — บอกว่าส่วนไหนของ IP คือ "เลขเครือข่าย" ส่วนไหนคือ "เลขเครื่อง" เช่น 255.255.255.0 (หรือเขียน /24) แปลว่า 3 ชุดแรกคือเครือข่าย
Default Gateway — ประตูออกจากเครือข่ายภายใน ปกติคือ IP ของ Router
MAC Address — หมายเลขประจำการ์ดเครือข่ายแต่ละใบ ถูกกำหนดมาจากโรงงาน เช่น 00:1A:2B:3C:4D:5E ใช้สื่อสารภายใน LAN

1.1.8 เครื่องมือตรวจสอบเครือข่ายเบื้องต้น
ping — ทดสอบว่าเข้าถึงอีกเครื่องได้หรือไม่ และใช้เวลาตอบกลับเท่าไร  (เช่น ping google.com)
ipconfig (Windows) / ifconfig, ip a (Linux/Mac) — ดู IP, Subnet Mask, Gateway ของเครื่อง
tracert / traceroute — ดูเส้นทาง (hop) ที่ข้อมูลผ่านไปจนถึงปลายทาง
nslookup — ตรวจสอบการแปลงชื่อโดเมนเป็น IP
เกิดอะไรขึ้นเมื่อเราพิมพ์ www.google.com แล้วกด Enter?
1) เบราว์เซอร์ถาม DNS ว่า google.com มี IP อะไร
2) เครื่องส่งข้อมูลผ่าน Router ออกไปยัง ISP และอินเทอร์เน็ตตามเส้นทางจนถึงเซิร์ฟเวอร์
3) สร้างการเชื่อมต่อ TCP + เข้ารหัส TLS (HTTPS)
4) เบราว์เซอร์ส่งคำขอ HTTP Request เซิร์ฟเวอร์ตอบ HTTP Response (หน้าเว็บ)
5) เบราว์เซอร์แสดงผลหน้าเว็บ
1.2 คลาวด์คอมพิวติ้ง (Cloud Computing)
1.2.1 นิยาม
Cloud Computing คือการ เช่าใช้ทรัพยากรคอมพิวเตอร์ (เซิร์ฟเวอร์ พื้นที่เก็บข้อมูล ฐานข้อมูล โปรแกรม เครือข่าย) ผ่านอินเทอร์เน็ต แทนที่จะซื้อและดูแลเครื่องเองทั้งหมด คิดค่าใช้จ่ายตามการใช้งานจริง (pay-as-you-go) ผู้ให้บริการรายใหญ่ เช่น AWS, Microsoft Azure, Google Cloud
เทคโนโลยีเบื้องหลังที่สำคัญคือ Virtualization — การแบ่งเซิร์ฟเวอร์จริงเครื่องเดียวออกเป็นเครื่องเสมือน (Virtual Machine) หลายเครื่อง ทำให้ใช้ทรัพยากรได้คุ้มค่า
1.2.2 คุณลักษณะสำคัญ
On-demand self-service — ขอใช้ทรัพยากรได้เองทันที
Broad network access — เข้าถึงได้จากหลายอุปกรณ์ผ่านเครือข่าย
Scalability / Elasticity — ขยาย/ลดทรัพยากรได้ตามความต้องการ
Resource pooling — ผู้ใช้หลายรายใช้ทรัพยากรร่วมกัน (แยกกันด้วยระบบความปลอดภัย)
Measured service — วัดการใช้งานและคิดเงินตามจริง
1.2.3 รูปแบบบริการ: IaaS / PaaS / SaaS
รูปแบบ
ผู้ให้บริการดูแล
ผู้ใช้ดูแลเอง
ตัวอย่าง
IaaS (Infrastructure as a Service)
ฮาร์ดแวร์ เครือข่าย การจำลองเสมือน
ระบบปฏิบัติการ โปรแกรม ข้อมูล
Amazon EC2, Azure VM, Google Compute Engine
PaaS (Platform as a Service)
ทุกอย่างของ IaaS + OS + Runtime
โค้ดและข้อมูลของแอป

SaaS (Software as a Service)

Gmail, Google Docs, Microsoft 365, Zoom
เปรียบเทียบกับการกินพิซซ่า
On-premises = ทำเองทุกอย่างที่บ้าน  |  IaaS = ซื้อวัตถุดิบ แต่เช่าครัว  |  PaaS = สั่งแป้งพร้อมอบ เติมหน้าเอง  |  SaaS = สั่งพิซซ่าสำเร็จรูปมากินเลย
1.2.4 รูปแบบการติดตั้ง (Deployment Models)
Public Cloud — ผู้ให้บริการเป็นเจ้าของ ใช้ร่วมกันหลายองค์กร (ถูก ขยายง่าย)
Private Cloud — ใช้เฉพาะองค์กรเดียว ควบคุมได้มากกว่า (ต้นทุนสูงกว่า)
Hybrid Cloud — ผสม Public + Private เช่น เก็บข้อมูลสำคัญไว้ใน Private ส่วนงานทั่วไปใช้ Public
1.2.5 ข้อดี ข้อเสีย และหลักความรับผิดชอบร่วมกัน
ข้อดี
ข้อควรระวัง
ลดต้นทุนลงทุนเริ่มต้น เริ่มใช้งานเร็ว ขยายง่าย เข้าถึงได้ทุกที่ สำรองข้อมูล/กู้คืนสะดวก
ต้องพึ่งอินเทอร์เน็ต ผูกติดผู้ให้บริการ (vendor lock-in) ค่าใช้จ่ายอาจบานปลายหากไม่ควบคุม ความเสี่ยงเรื่องข้อมูลและความเป็นส่วนตัวหากตั้งค่าผิด
Shared Responsibility Model: ผู้ให้บริการรับผิดชอบความปลอดภัย "ของ" คลาวด์ (ศูนย์ข้อมูล ฮาร์ดแวร์) ส่วนผู้ใช้ต้องรับผิดชอบความปลอดภัย "ในคลาวด์" (รหัสผ่าน สิทธิ์การเข้าถึง การตั้งค่า ข้อมูลของตน) — ข้อมูลรั่วจากคลาวด์ส่วนใหญ่เกิดจาก การตั้งค่าผิดพลาดของผู้ใช้ ไม่ใช่เพราะคลาวด์เองไม่ปลอดภัย
1.3 ความมั่นคงปลอดภัยไซเบอร์ (Cybersecurity) และ InfoSec
1.3.1 InfoSec vs Cybersecurity
Information Security (InfoSec) คือการปกป้อง "ข้อมูล" ในทุกรูปแบบ (ดิจิทัล กระดาษ คำพูด) ส่วน Cybersecurity เน้นปกป้องระบบคอมพิวเตอร์ เครือข่าย และข้อมูลดิจิทัลจากการโจมตีทางไซเบอร์ — Cybersecurity จึงเป็นส่วนหนึ่งของ InfoSec

1.3.3 ภัยคุกคามที่พบบ่อย
ภัย
อธิบายสั้นๆ
Virus
โปรแกรมอันตรายที่แนบกับไฟล์อื่นและแพร่ต่อเมื่อไฟล์ถูกเปิดใช้งาน
Worm
แพร่กระจายผ่านเครือข่ายได้เอง โดยไม่ต้องมีคนเปิดไฟล์
Trojan
ปลอมตัวเป็นโปรแกรมปกติ แต่แอบทำสิ่งไม่ดีในเบื้องหลัง
Ransomware
เข้ารหัสไฟล์ของเหยื่อแล้วเรียกค่าไถ่เพื่อแลกกับกุญแจปลดล็อก
Spyware / Keylogger
แอบสอดแนมพฤติกรรม/บันทึกการพิมพ์เพื่อขโมยรหัสผ่านหรือข้อมูล
Phishing
หลอกลวงผ่านอีเมล/SMS/เว็บปลอม ให้เหยื่อกรอกข้อมูลสำคัญหรือกดลิงก์อันตราย
Social Engineering
หลอกใช้จิตวิทยามนุษย์ เช่น แอบอ้างเป็นเจ้าหน้าที่ เพื่อให้เหยื่อบอกข้อมูลเอง
Brute Force
เดารหัสผ่านทุกความเป็นไปได้ไปเรื่อยๆ จนถูก
DoS / DDoS
ส่งคำขอจำนวนมหาศาลให้เซิร์ฟเวอร์จนใช้งานไม่ได้ (DDoS มาจากหลายเครื่องพร้อมกัน)
Man-in-the-Middle
แอบดักอยู่ระหว่างผู้ส่งกับผู้รับเพื่อแอบดูหรือแก้ไขข้อมูล (พบบ่อยใน Wi-Fi สาธารณะ)
SQL Injection
แทรกคำสั่ง SQL ผ่านช่องกรอกข้อมูลเพื่อเจาะฐานข้อมูล
1.3.4 วิธีป้องกันเบื้องต้น
รหัสผ่านที่ดี: ยาว (12 ตัวอักษรขึ้นไป) ไม่ซ้ำกันในแต่ละบริการ ไม่ใช้ข้อมูลส่วนตัวที่เดาง่าย — ใช้ Password Manager ช่วยจัดการ
MFA / 2FA (Multi-Factor Authentication): ยืนยันตัวตนหลายปัจจัย เช่น สิ่งที่รู้ (รหัสผ่าน) + สิ่งที่มี (รหัส OTP/แอปยืนยัน) + สิ่งที่เป็น (ลายนิ้วมือ/ใบหน้า)
อัปเดตระบบและโปรแกรมสม่ำเสมอ เพื่อปิดช่องโหว่ (patch)
Firewall และ Antivirus — ช่วยป้องกัน แต่ไม่ใช่ทุกอย่าง ต้องใช้ร่วมกับพฤติกรรมที่ปลอดภัย
Backup แบบ 3-2-1: สำรองข้อมูล 3 ชุด บน 2 สื่อ/ที่เก็บต่างชนิด และ 1 ชุดเก็บนอกสถานที่ (หรือบนคลาวด์)
หลักสิทธิ์ขั้นต่ำ (Least Privilege): ให้สิทธิ์เท่าที่จำเป็นต่อการทำงานเท่านั้น
VPN: สร้างอุโมงค์เข้ารหัสระหว่างอุปกรณ์กับเครือข่ายปลายทาง ช่วยเมื่อใช้ Wi-Fi สาธารณะ
ระวัง Phishing: ตรวจที่อยู่ผู้ส่ง ดูชื่อโดเมนของลิงก์ให้ดี อย่ากดลิงก์/ไฟล์แนบที่ไม่คาดคิดหรือเร่งรัดให้รีบทำ

2) วนซ้ำแบบรู้จำนวนรอบ (for) และ แบบไม่รู้จำนวนรอบ (while)

n = 3

2.2.1 อัลกอริทึมคืออะไร
อัลกอริทึม คือ ลำดับขั้นตอนที่ชัดเจนและจำกัดจำนวน เพื่อแก้ปัญหาหนึ่งๆ เหมือนสูตรอาหารที่บอกทุกขั้นตอน คุณสมบัติของอัลกอริทึมที่ดี:
มี Input (ข้อมูลนำเข้า) และ Output (ผลลัพธ์) อย่างน้อย 1 อย่าง
ชัดเจน (Definiteness) ทุกขั้นตอนไม่กำกวม
จำกัด (Finiteness) ต้องจบได้ในจำนวนขั้นตอนที่จำกัด
มีประสิทธิภาพ (Effectiveness) ทำได้จริง และไม่ใช้ทรัพยากรเกินจำเป็น

2.3 ปัญญาประดิษฐ์ (AI) เบื้องต้น
2.3.1 AI คืออะไร และความสัมพันธ์กับ ML / DL
ปัญญาประดิษฐ์ (Artificial Intelligence: AI) คือระบบคอมพิวเตอร์ที่ทำงานที่ปกติต้องใช้ปัญญามนุษย์ เช่น เข้าใจภาษา จดจำภาพ ตัดสินใจ เรียนรู้ มีความสัมพันธ์แบบวงกลมซ้อนกัน:
AI — แนวคิดกว้างที่สุด
Machine Learning (ML) — ส่วนหนึ่งของ AI: ให้เครื่อง เรียนรู้รูปแบบจากข้อมูล แทนที่จะเขียนกฎเองทั้งหมด
Deep Learning (DL) — ส่วนหนึ่งของ ML: ใช้ โครงข่ายประสาทเทียม (Neural Network) หลายชั้น เก่งกับภาพ เสียง ภาษา
Generative AI — AI ที่ "สร้าง" เนื้อหาใหม่ (ข้อความ ภาพ เสียง โค้ด) เช่น ChatGPT, Claude, Gemini, ตัวสร้างภาพ

1) กำหนดปัญหา  2) เก็บข้อมูล  3) เตรียม/ทำความสะอาดข้อมูล  4) แบ่งข้อมูลเป็นชุด Train (สอน) และ Test (ทดสอบ)  5) ฝึกโมเดล  6) ประเมินผล (เช่น ความแม่นยำ Accuracy)  7) นำไปใช้และปรับปรุง
คำสำคัญ: Overfitting = โมเดล "ท่องจำ" ข้อมูลสอนจนเก่งแต่กับข้อมูลที่เคยเห็น แต่ใช้กับข้อมูลใหม่ไม่ดี  |  Garbage In, Garbage Out = ข้อมูลไม่ดี โมเดลก็ไม่ดี
2.3.5 Generative AI และ LLM เบื้องต้น
LLM (Large Language Model) — โมเดลภาษาขนาดใหญ่ ฝึกจากข้อความจำนวนมหาศาล ทำงานโดยทำนาย "คำ/ส่วนของคำถัดไป" ที่น่าจะเป็นไปได้ จึงตอบ สรุป แปล เขียนโค้ดได้
Prompt — คำสั่ง/คำถามที่เราพิมพ์ให้ AI  Prompt ที่ดีควรชัดเจน มีบริบท ระบุรูปแบบผลลัพธ์ที่ต้องการ
Hallucination (การมโนข้อมูล) — AI สร้างข้อมูลที่ฟังดูน่าเชื่อถือแต่ ไม่เป็นความจริง จึงต้องตรวจสอบข้อมูลสำคัญเสมอ
2.3.6 ข้อจำกัดและจริยธรรมของ AI
อคติ (Bias) — ข้อมูลที่ใช้สอนลำเอียง ผลลัพธ์ก็ลำเอียง เช่น ระบบคัดเลือกคนที่เคยเลือกแต่ผู้ชาย
ความเป็นส่วนตัว — ไม่ควรใส่ข้อมูลส่วนตัว/ความลับขององค์กรลงในเครื่องมือ AI โดยไม่ระวัง
ความรับผิดชอบ — มนุษย์ยังต้องรับผิดชอบการตัดสินใจ ไม่ควรเชื่อ AI โดยไม่ตรวจสอบ
ลิขสิทธิ์และความซื่อสัตย์ทางวิชาการ — ระบุการใช้ AI ช่วยงาน และไม่คัดลอกเป็นผลงานตนเองโดยไม่บอก
Deepfake / ข้อมูลเท็จ — AI สร้างภาพ เสียง วิดีโอปลอมที่สมจริงได้ ต้องตรวจสอบแหล่งที่มา

• อัลกอริทึม = ขั้นตอนแก้ปัญหาที่ชัดเจนและจำกัด เขียนได้ด้วยรหัสเทียมหรือผังงาน

3.3 การสื่อสารและพลเมืองดิจิทัล
3.3.1 มารยาทในโลกออนไลน์ (Netiquette)
สุภาพ เคารพผู้อื่น ไม่ใช้คำหยาบ ไม่ใช้อารมณ์ในการโพสต์/ตอบ
คิดก่อนโพสต์ — สิ่งที่โพสต์แล้วอาจถูกแคปหน้าจอและอยู่ต่อไปอีกนาน
ไม่พิมพ์ตัวพิมพ์ใหญ่ทั้งประโยค (ถูกตีความว่าตะโกน) ในภาษาอังกฤษ
ใช้หัวข้ออีเมลที่ชัดเจน ทักทายและลงท้ายอย่างเหมาะสมในสถานการณ์ทางการ
ไม่เผยแพร่ภาพ/ข้อมูลของผู้อื่นโดยไม่ได้รับอนุญาต
3.3.2 การกลั่นแกล้งออนไลน์ (Cyberbullying)
การใช้สื่อดิจิทัลข่มขู่ ล้อเลียน ประจาน หรือทำให้ผู้อื่นเสียหาย วิธีรับมือ: ไม่โต้ตอบด้วยอารมณ์ / เก็บหลักฐาน (แคปหน้าจอ) / บล็อกและรายงานบัญชี / บอกผู้ใหญ่หรือบุคคลที่ไว้ใจ / หากรุนแรงแจ้งความหรือขอความช่วยเหลือจากหน่วยงานที่เกี่ยวข้อง
3.3.3 ร่องรอยดิจิทัล (Digital Footprint)
ทุกอย่างที่เราทำออนไลน์ทิ้งร่องรอยไว้ แบ่งเป็น Active (ที่เราตั้งใจโพสต์ เช่น โพสต์ รูป คอมเมนต์) และ Passive (ที่ถูกเก็บโดยที่เราอาจไม่รู้ เช่น ประวัติการเข้าชม คุกกี้ ตำแหน่งที่ตั้ง)
ลดความเสี่ยง: ตั้งค่าความเป็นส่วนตัวของโซเชียล / ไม่โพสต์ข้อมูลอ่อนไหว (เลขบัตร ที่อยู่ตารางเวลาประจำวัน) / ตรวจสอบสิทธิ์ที่แอปขอ / ค้นชื่อตัวเองเป็นระยะ / ลบบัญชีที่ไม่ใช้แล้ว

ข้อมูลทั่วไป

3.4.3 กฎหมายคอมพิวเตอร์และความรับผิดชอบ
ประเทศไทยมี พ.ร.บ.ว่าด้วยการกระทำความผิดเกี่ยวกับคอมพิวเตอร์ ที่ห้ามกระทำ เช่น เข้าถึงระบบหรือข้อมูลโดยมิชอบ นำข้อมูลคอมพิวเตอร์อันเป็นเท็จเข้าสู่ระบบจนเกิดความเสียหาย หรือเผยแพร่ข้อมูลที่ผิดกฎหมาย (รายละเอียดอาจมีการแก้ไขตามช่วงเวลา ควรตรวจสอบจากแหล่งทางการ) หลักง่ายๆ คือ โลกออนไลน์ก็มีกฎหมายเหมือนโลกจริง

4.3.3 กฎที่ควรรู้
นิเสธซ้อน: ¬(¬p) ≡ p
กฎเดอ มอร์แกน: ¬(p ∧ q) ≡ ¬p ∨ ¬q  และ  ¬(p ∨ q) ≡ ¬p ∧ ¬q  (เช่น "ไม่ใช่ทั้งชอบเค้กและชอบไอศกรีม" = "ไม่ชอบเค้ก หรือ ไม่ชอบไอศกรีม")
Contrapositive: p → q ≡ ¬q → ¬p  (ถ้า "ฝนตก → ถนนเปียก" จริง แล้ว "ถนนไม่เปียก → ฝนไม่ตก" ก็จริงด้วย)
ข้อผิดพลาดที่พบบ่อย: จาก "ถ้าฝนตก แล้วถนนเปียก" และ "ถนนเปียก" สรุปไม่ได้ ว่าฝนตก (อาจเพราะรถน้ำล้างถนน)

4.5.2 เซตและแผนภาพเวนน์เบื้องต้น
สูตรสำคัญ: n(A ∪ B) = n(A) + n(B) − n(A ∩ B)
ตัวอย่าง: นักเรียน 30 คน ชอบฟุตบอล 18 คน ชอบบาสเกตบอล 15 คน ชอบทั้งสองอย่าง 5 คน → ชอบอย่างน้อยหนึ่งอย่าง = 18 + 15 − 5 = 28 คน  → ไม่ชอบเลย = 30 − 28 = 2 คน
4.5.3 การนับเบื้องต้น
กฎการคูณ: ทำงานเป็นขั้นๆ ขั้นที่ 1 ทำได้ m วิธี ขั้นที่ 2 ทำได้ n วิธี รวม m × n วิธี เช่น เสื้อ 3 ตัว กางเกง 2 ตัว → แต่งตัวได้ 3 × 2 = 6 แบบ
กฎการบวก: เลือกอย่างใดอย่างหนึ่ง ไม่ซ้ำกัน รวม m + n วิธี เช่น เดินทางด้วยรถ 3 สาย หรือเรือ 2 เส้นทาง = 5 วิธี
การเรียงสับเปลี่ยน: เรียงของ n สิ่งที่ต่างกัน = n! เช่น เรียงคน 3 คนเป็นแถว = 3! = 3×2×1 = 6 วิธี
การจับมือ: คน n คน จับมือกันทุกคู่ = n(n−1)/2 เช่น 5 คน = 5×4/2 = 10 ครั้ง
4.6 ตัวอย่างโจทย์ปริศนาตรรกะ พร้อมวิธีคิด
ตัวอย่างที่ 1: การเรียงลำดับ
โจทย์: แดงสูงกว่าเขียว, เขียวสูงกว่าน้ำเงิน, ส้มเตี้ยกว่าน้ำเงิน ใครสูงที่สุด ใครเตี้ยที่สุด
วิธีคิด: เรียงจากเงื่อนไข → แดง > เขียว > น้ำเงิน > ส้ม  ดังนั้น แดงสูงสุด ส้มเตี้ยสุด
ตัวอย่างที่ 2: คนพูดจริง/คนโกหก
โจทย์: A บอกว่า "B โกหก" และ B บอกว่า "A กับ B พูดจริงทั้งคู่" ใครพูดจริง? (แต่ละคนพูดจริงหรือโกหกอย่างใดอย่างหนึ่ง)
วิธีคิด: สมมติ B พูดจริง → A กับ B จริงทั้งคู่ → แต่ A บอกว่า B โกหก ขัดแย้ง ✘  ดังนั้น B โกหก → A ที่บอกว่า "B โกหก" จึงพูดจริง  สรุป A พูดจริง B โกหก  (ตรวจ: ประโยคของ B เป็นเท็จจริงเพราะ B ไม่ได้พูดจริง ✔)
ตัวอย่างที่ 3: ทำย้อนกลับ
โจทย์: คิดเลขหนึ่งตัว คูณ 3 แล้วบวก 4 ได้ 19 เลขนั้นคืออะไร
วิธีคิด: ย้อนกลับ → 19 − 4 = 15 → 15 ÷ 3 = 5  (ตรวจ: 5×3+4 = 19 ✔)
สรุปเสาที่ 4 ใน 5 บรรทัด
• แก้ปัญหาตามขั้นตอน: เข้าใจ → วางแผน → ลงมือ → ตรวจสอบ
• Computational Thinking = แยกย่อย + หารูปแบบ + คิดเชิงนามธรรม + ออกแบบขั้นตอน
• ตรรกะ: AND จริงเมื่อจริงทั้งคู่ / OR จริงเมื่อจริงอย่างน้อยหนึ่ง / NOT กลับค่า / IF-THEN เท็จเฉพาะ T→F
• นิรนัยแน่นอนกว่าอุปนัย; ระวัง Fallacy และอย่าสรุปจากหลักฐานน้อยเกินไป
• ฝึกด้วยลำดับ เซต การนับ และปริศนา — แล้วตรวจคำตอบทุกครั้ง

1. ตอบ ข — LAN = Local Area Network เครือข่ายในพื้นที่จำกัด (ข้อ ง คือ PAN)

3. ตอบ ง — ช่วง 192.168.x.x เป็นช่วง Private IP ส่วนข้ออื่นเป็นที่อยู่แบบสาธารณะ

9. ตอบ ค — การผสม Private + Public คือ Hybrid Cloud
10. ตอบ ข — Integrity = ความถูกต้องครบถ้วนของข้อมูล
11. ตอบ ค — Ransomware = มัลแวร์เรียกค่าไถ่

14. ตอบ ข — ข้อมูล 3 ชุด / 2 สื่อ / 1 ชุดเก็บนอกสถานที่

1. แนวคำตอบ:

SaaS: ซอฟต์แวร์พร้อมใช้งานผ่านเว็บ ผู้ใช้แค่ใช้งาน เช่น Gmail
2. แนวคำตอบ:
1) เบราว์เซอร์ถาม DNS เพื่อแปลงชื่อโดเมนเป็น IP  2) ส่งคำขอผ่าน Router/ISP ไปยังเซิร์ฟเวอร์ปลายทาง  3) สร้างการเชื่อมต่อ TCP และ TLS (กรณี HTTPS)  4) ส่ง HTTP Request และรับ HTTP Response  5) เบราว์เซอร์แสดงผลหน้าเว็บ

ตรวจ: ประโยคของ C ("A และ B โกหกทั้งคู่") เป็นเท็จจริง เพราะ B จริง ✔
